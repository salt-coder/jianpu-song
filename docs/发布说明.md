# 发布说明（GitHub）

本仓库**只放源码**；约 90 MB 的便携包与技能包通过 **Release 附件**发布。
这样仓库历史保持干净，别人下载也方便。

---

## 一、第一次推送到 GitHub

### 1. 在 GitHub 上新建空仓库

打开 <https://github.com/new>：

| 项目 | 建议 |
|---|---|
| Repository name | `jianpu-song` |
| Description | `简谱数字 → 音频（287 种 GM 音色）+ QQ Agent 语音点歌技能` |
| 可见性 | Public（要开源）或 Private |
| **Initialize this repository** | ⚠️ **全部不要勾**（不要 README / .gitignore / license）——本地已经有了 |

### 2. 本地推送

本仓库已经 `git init` 并完成首次提交，直接绑定远端并推送即可：

```bash
cd D:\deepseek\jianpu-song

git remote add origin https://github.com/<你的用户名>/jianpu-song.git
git branch -M main
git push -u origin main
```

> 首次推送会要求登录：推荐用 **GitHub Desktop**，或 `git config --global credential.helper manager`
> 后输入 **Personal Access Token**（不是密码）。

### 3. 改提交者身份（可选）

首次提交用的是本地配置的 `dove <dove@users.noreply.github.com>`（不会暴露真实邮箱）。
想换成别的：

```bash
git config user.name  "你的名字"
git config user.email "你的邮箱或GitHub用户名@users.noreply.github.com"
git commit --amend --reset-author --no-edit
```

## 二、发布 Release（上传便携包）

⚠️ **不要把 zip 直接 `git add` 提交** —— 90 MB 的二进制会永久留在 git 历史里，
以后每更新一次再 +90 MB，仓库很快就几个 GB。

正确做法是用 **Release 附件**（单文件上限 2 GB，不进 git 历史）：

1. 打开仓库页面 → 右侧 **Releases** → **Draft a new release**
2. **Choose a tag** → 输入 `v1.0.0` → 点 *Create new tag*
3. Release title：`v1.0.0 —— 简谱转音乐 + QQ Agent 技能`
4. 描述里贴上（**署名要求在 [`THIRD-PARTY-LICENSES.md`](../THIRD-PARTY-LICENSES.md) 第四节**）：
   ```
   ## 下载
   - jianpu-portable.zip       便携版（命令行用，解压即用，需 Python 3.8+）
   - qqagent-jianpu-skill.zip  给 QQ Agent 的技能包（含工具链 + 一键安装）

   ## 需要什么
   只装 Python 3.8+（安装时勾选 Add python.exe to PATH），ffmpeg / Node / 音源都已在包内。

   ## 首次使用
   解压后双击 run.cmd，或：
       python -X utf8 3.py "1 2 3 1|3 4 5-" --engine sf2 --gm 钢琴 -o out.mp3

   ## 第三方组件
   GeneralUser GS v2.0.3 by S. Christian Collins · basic-harmonica (CC0) ·
   FFmpeg (GPL v3, gyan.dev build) · Node.js (MIT) · FluidSynth (LGPL-2.1) · js-synthesizer (MIT)
   详见 THIRD-PARTY-LICENSES.md
   ```
5. 把两个 zip **拖进** "Attach binaries by dropping them here" 区域
6. **Publish release** ✅

## 三、便携包是怎么拼出来的（自己重新打包时看这里）

```
jianpu-portable/
├── 3.py                 ← 仓库 src/3.py
├── run.cmd              ← 仓库 scripts/run.cmd
├── sf2_render.cjs       ← 仓库 src/sf2_render.cjs
├── 使用说明.md / 授权说明.md
├── engine/              ← js-synthesizer 的 dist/js-synthesizer.min.js + externals/libfluidsynth-2.4.6.js
├── soundfonts/          ← GeneralUser GS 2.0.3（GeneralUser-GS.sf2）
├── ffmpeg/bin/          ← ffmpeg 7.1 essentials build（gyan.dev）
├── node/                ← node.exe（Node.js v24 Windows x64）
└── harmonica/           ← basic-harmonica 的 SFZ + wav 采样
```

### 各组件的获取方式

| 组件 | 来源 |
|---|---|
| js-synthesizer + FluidSynth wasm | `npm pack js-synthesizer` → 解包，取 `dist/js-synthesizer.min.js` 与 `externals/libfluidsynth-2.4.6.js` |
| GeneralUser GS | <https://schristiancollins.com/generaluser.php>（或 GitHub `mrbumpy409/GeneralUser-GS`） |
| ffmpeg | <https://www.gyan.dev/ffmpeg/builds/> → `ffmpeg-release-essentials.zip` → 取 `bin/ffmpeg.exe` |
| Node.js | <https://nodejs.org/> → Windows x64 zip → 取 `node.exe` |
| basic-harmonica | GitHub `basic-harmonica` → `harmonica solo.sfz` + `samples/`（转成 wav 放 `harmonica/wav/`） |

### 必需的目录约束（`3.py` 靠这些相对位置自动查找）

- `3.py` 与 `engine/`、`soundfonts/`、`ffmpeg/`、`node/`、`harmonica/` **同级**
- `engine/` 里要有 `libfluidsynth-2.4.6.js` 与 `js-synthesizer.min.js`
- ⚠️ **`engine/` 里要放一个 `package.json`，内容 `{"type":"commonjs"}`** ——
  否则当便携包被放进带 `"type":"module"` 的工程（例如 QQ Agent 的 `resources/app`）时，
  Node 会把引擎当成 ESM，UMD 包装会崩，表现为"音色悄悄降级成正弦波"

### 技能包（`qqagent-jianpu-skill.zip`）

```
qqagent-skill-bundle/
├── 安装说明.md / 一键安装.cmd     ← 仓库 qqagent-skill/
├── skills/jianpu-song/           ← 仓库 qqagent-skill/jianpu-song/
└── jianpu-tools/                 ← 与便携包内容相同（3.py + 依赖）
```

安装脚本会把 `skills/jianpu-song` 复制到 QQ Agent 的 `resources/app/skills/`，
把 `jianpu-tools` 复制到 `resources/app/`（技能会自动找到它）。
